# 需求是长期功能，一次开发只是一次改动

早期把一次请求当成一条需求，开发记录与需求一一对应：每次改动都新建一条需求，以前定下的规矩只留在旧需求里，Main 开工前没有一处能读到“这个功能现在怎样”。改为：需求代表一块长期功能，保存一直更新的现状、每次改动的一条历史和用户对它的其他叫法（别名），同一需求可以挂多次开发；与任何功能都无关的改动记入每个项目固定的一条 `misc` 需求，不为它新建需求。这样 Main 在设计前能读到一块功能的现行约定，需求 ID 长期稳定，台账、看板和记忆都能按它引用。持久表见 [项目数据迁移](../../src/storage/project-data/migrations.ts)：需求、需求历史与开发记录按这个模型保存，改回“一请求一需求”要迁移已有需求、历史和开发的关联。
