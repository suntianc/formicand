# 记忆与上下文压缩设计

状态：2026-11-20 草案，待确认。所属阶段见 [P4.9](development-phases.md#p49记忆与上下文压缩)。

## 一、为什么重做

**压缩。** Main 与子代理现在都用 Pi 的原生压缩：上下文快满时，把较早的对话交给模型写成一份分栏摘要，替换原文，最近一段原样保留。问题有三处：

- 摘要会丢东西。用户早先定的约束、试过不行的办法、具体的报错，写进摘要后变成一两句话，或者干脆没了；之后 Main 只能凭摘要继续。
- 实现脆弱。为了改写摘要要求，[compaction-summary-policy](../src/runtime/compaction-summary-policy.ts) 逐字匹配 Pi 自带的总结提示词再替换，Pi 一改措辞就失效。它也是依赖边界里的临时例外。
- 每次压缩都要多调一次模型，失败了还要冷却重试（[失败冷却](../src/runtime/compaction-failure-backoff.ts)）。

**记忆。** P4.6 删除了原来的个人记忆、自动学习与项目经验，P4.8 又删除了 `memory.md` 进度笔记。原来那套的问题（据当时的设计文档判断）：

- 后台另调模型，从用户原话里"提炼偏好"，还要在三个不同会话里出现才转正，规则很多，结果难以预料；
- 所有记忆挤在一份最多 2000 字的正文里，每次整段注入；
- 记什么、不记什么没有清楚的界限，容易记下代码里本来就有的东西。

## 二、参考

**Claude Code** 的压缩分几级，先用不调模型的办法，实在不够才写摘要（以下分级来自对其代码的反向分析，官方文档只确认了摘要与压缩后重新装回）：

1. 大的工具结果存到磁盘，上下文只留路径；
2. 很早的读文件、列目录等消息挪走，原位换成小标记；
3. 用到 90% 左右，从最老的一段起逐段写小摘要；
4. 快满时整体写摘要，再从磁盘重新装回项目说明、记忆索引、技能、最近改过的文件和待办；
5. 接口报"请求太长"时应急压缩，只留最后几条。

它的原则是：不能丢的（规则、记忆、计划）放在文件里，每次压缩后重新装回，不靠摘要保存。记忆按项目存，一个索引文件每条一行、每条单独一个文件，只记四类：用户本人、用户的纠正与认可、代码和提交记录看不出来的项目情况、外部资料的位置。

**Codex 实验模式**（`features.context_management.experimental_mode`，源码 `openai/codex`）根本不写摘要：

- 上下文用完或模型觉得没用时，开一个新窗口，"不总结对话历史"。新窗口只放系统提示、项目说明、当前环境状态和标了"跨窗口保留"的条目；
- 模型自己记笔记（列、读、搜、追加、改写），每个新窗口开头放一段不超过 4000 字节的笔记提示；
- 旧窗口不删，模型可以列出、读取、按关键字搜索；
- 每次告诉模型还剩多少容量，低于某个值时提醒一次。

**Anthropic 接口**的"清除旧工具结果"：超过阈值后，从最早的工具结果起换成"已清除"占位，保留最近几次，可排除指定工具，每次至少清掉一定数量以免频繁打破缓存。快清除前提醒模型先把要紧的记下来。

## 三、上下文管理

结合两者：先用 Claude Code 前两级那样不调模型的办法推迟压缩；到了必须腾空间时，按 Codex 的方式换窗口，不写摘要；新窗口里装回的东西由程序从记录生成，再加 Main 自己的笔记和可查的历史。

### 分级

| 级别          | 触发（初始值，实测后调）                                          | 做什么                                                                                                                            | 调模型 |
| ------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1. 大结果落盘 | 单个工具结果超过 2 万字符                                         | 原文存进会话目录，上下文里留开头、结尾和路径                                                                                      | 否     |
| 2. 清旧结果   | 上下文超过窗口的 50%，回合结束时                                  | 最近 5 次以外的工具结果换成一行占位（工具名、调用编号、"原文可用 `read_history` 取回"）；工具调用本身保留；一次至少腾出窗口的 10% | 否     |
| 3. 容量提醒   | 上下文超过窗口的 75%，每个窗口一次                                | 告诉 Main 还剩多少，提醒把还要用的记进笔记                                                                                        | 否     |
| 4. 换窗口     | 超过 Pi 的压缩阈值；或 Main 调 `clear_context`；或用户 `/compact` | 写入程序生成的交接页（见下），只保留最近一小段原文                                                                                | 否     |
| 5. 应急       | 接口报上下文超长                                                  | 同第 4 级，但不保留原文尾部；交接页本身过长时，较早的用户原话换成编号引用                                                         | 否     |

五级都不调模型，所以压缩不会失败，也不再需要失败冷却。Main 与子代理共用同一套。

第 2 级不清除的工具：`load_skill`（技能正文）、`askhuman` 的问答、`project_development` 最近一次结果。哪些工具结果必须保留，实施时逐个确认。

### 换窗口后的交接页

全部由程序按记录生成，按下面顺序，整体有上限（初定 3 万字符）：

1. **用户说过的话**：本会话所有用户消息原文，按时间排列。超出预算时，最早的换成"第 N 条，可用 `read_history` 取回"，最近的保留原文。
2. **需求进度**：当前开发记录的目标、完成标准、路线；票的清单与状态；最近一次 `next`。直接取自开发记录，不由模型复述。
3. **进行中的事**：未结束的委派（谁、做什么、派出时间），未回答的提问。
4. **Main 的笔记**：笔记文件全文，有单独上限（初定 8000 字符），超出时提示 Main 精简。
5. **最近碰过的文件**：最近读写过的文件路径（不附内容）。
6. **一句说明**：这是新窗口，旧历史没有删除，可用 `search_history`、`read_history` 查。

系统提示、技能目录、项目说明和记忆索引本来就每次刷新，不进交接页。

### 新工具

- `session_notes`：读、追加、整篇改写本会话的笔记。笔记存在会话目录，跨窗口保留，暂停、重启后仍在（接续原会话）。
- `search_history`：在本会话完整历史里按关键字搜，可按角色、工具名过滤，返回条目编号和片段。
- `read_history`：按条目编号读原文，可指定起止位置。

`clear_context` 保留，含义改为"现在换窗口"，与 Codex 的 `new_context` 相同。

### 用 Pi 的什么实现

Pi 1.5.2 已提供所需接口，不必再改 Pi 的提示词：

- 第 4、5 级：`session_before_compact` 返回我们自己的 `compaction`（交接页作为 `summary`，自定 `firstKeptEntryId`），Pi 不再调模型写摘要。触发时机仍由 Pi 的压缩设置决定，`reason` 区分手动、阈值和超长。
- 第 2 级：在 `turn_end` 边界追加 `context_edit` 条目，把目标工具结果的内容换成占位。它写在会话记录里，只改模型看到的内容，完整历史不变；一批一次写入，缓存只断一次。
- 第 1 级：在工具结果返回时落盘并替换内容。
- 第 3 级：`context` 事件里加一条提醒，或在边界追加一条自定义消息。

做完后删除 `compaction-summary-guard`、`compaction-summary-policy`、`compaction-failure-backoff`、`compaction-input` 与 `main-compaction` 中只为摘要服务的部分，并从依赖边界规则里收回压缩例外。

### 界面

- 输入框 `/compact`：立即换窗口。
- 对话里显示"已换新窗口"的分隔，点开可看交接页。
- 上下文用量在对话面板可见（已用多少、第几个窗口）。

## 四、记忆

照 Claude Code 的做法：Main 自己判断后直接写，不另调模型提炼；用户随时查看、修改、删除。

### 记什么

| 类型       | 记什么                                       | 例子                               |
| ---------- | -------------------------------------------- | ---------------------------------- |
| 用户       | 用户的角色、熟悉什么、习惯                   | 英文不好，回复用中文大白话         |
| 纠正与认可 | 用户纠正过的做法、确认过的做法，附原因       | 合入前每次都要用户同意             |
| 项目情况   | 代码和记录里看不出来的进行中的事、决定、期限 | 拆票要等真实需求再测，暂不改提示词 |
| 外部资料   | 别处的资料在哪                               | 某个看板、文档的地址               |

不记：看代码就能知道的（结构、路径、修过的问题）；项目说明（AGENTS.md）里已经写了的；需求台账、开发记录和票里已有的（需求、验收标准、进度）；只跟当前会话有关的（写进会话笔记）。

### 存在哪、怎么进入对话

- 两级：用户级（跨项目，`ATRIA_HOME/memory/user/`）与项目级（按项目 ID，`ATRIA_HOME/memory/projects/<projectId>/`）。不写进用户的仓库。
- 每条记忆一个文件，带名称、类型、一句话说明和更新时间。索引由程序从这些文件生成，每条一行"名称 [类型, 日期] 一句话"，不另存索引文件，所以不会和内容对不上。
- 每次请求把两级索引放进系统提示的 `memory` 一节（合计最多 1.2 万字符，装不下的旧条目只报条数，提示 Main 列出查看）；具体内容用到时再读。压缩换窗口后自然仍在。每一级最多 80 条，满了要先合并或删除旧的。
- 子代理不自动获得记忆，由 Main 在任务里传递相关的部分。

### 工具与界面

- `memory`：列出、读取、写入、删除，参数里指定用户级还是项目级。写入前先查有没有已有的一条可以更新，避免重复。智能体不能直接读写 CoworkOS 的数据目录（P4.6 定的边界），所以用专门的工具。
- 设置里新增「记忆」：按两级列出，可查看、修改、删除；项目级可整体关闭。

### 会话笔记、记忆、记录怎么分工

| 内容                           | 放在哪               | 寿命     |
| ------------------------------ | -------------------- | -------- |
| 需求、完成标准、票、进度       | 开发记录与票         | 跟需求走 |
| 项目背景、历史需求与决定       | 需求台账             | 跟项目走 |
| 本会话做到哪、试过什么、待查的 | 会话笔记             | 跟会话走 |
| 跨会话仍有用的人和项目情况     | 记忆                 | 直到删除 |
| 对话原文                       | 会话历史（可搜可读） | 跟会话走 |

## 五、验证

- 真实 Pi 进程、本地假模型：每一级的触发与结果；换窗口后交接页内容、`search_history`/`read_history` 取回原文；暂停与重启后笔记仍在；子代理同样换窗口；超长时应急一定成功。
- 记忆：两级写入、读取、删除；索引进入系统提示；设置页查看与修改；子代理拿不到。
- 实测任务集加两个任务：
  - 长会话：把上下文窗口设小，迫使任务中途换窗口多次，看换窗口后是否仍守住早先的约束、不重复已做的事；新旧压缩各跑一次对比；
  - 跨会话记忆：第一个会话里纠正一次做法，第二个会话里看是否照做。
- 体积：交接页、记忆索引、新工具说明的上限由测试检查。

## 六、实施顺序

每一步单独开分支、单独合入。

1. 第 1、2 级（落盘与清旧结果），加上下文用量显示。只推迟压缩，不改压缩本身，最容易单独验证。
2. 会话笔记与 `search_history`/`read_history`。
3. 第 3～5 级：容量提醒、程序生成的交接页、`/compact`；删除摘要相关代码，收回依赖边界例外。
4. 记忆：存储、`memory` 工具、索引注入、设置页。
5. 实测对比，记录结果。

## 七、待定

- 各级阈值与上限都是初始值，按第 5 步实测调整。
- 交接页是否需要一段模型写的"当前在做什么"。初步不要：笔记由 Main 自己写，作用相同且不会被改写；实测发现换窗口后接不上时再考虑。
- 对外 Main（P5）的记忆：客户消息不能变成记忆里的指令，随 P5 一起定。本阶段只做对内。
