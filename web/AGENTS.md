# 共用前端

`app.js` 装配页面状态和控制器；新行为优先进入 `assets/controllers/` 或 `assets/ui/` 的现有模块。Web 与 Electron 共用页面，浏览器模块不导入 Node。

- 控制器用明确端口/回调协作，不跨模块直接修改私有状态或复制请求逻辑。
- 异步操作捕获 Task、草稿和导航身份，晚返回不覆盖新的选择、草稿或会话。刷新复用焦点与滚动位置。
- 草稿与附件在关闭、重启和切换会话时保留；产物只读预览不写回文件。
- SSE 连接、重连、去重和清理由 connection controller 管理；不要另开一套事件通道。
- 产品 UI 只展示用户需要的信息，工程诊断放到日志/文档。文案与层级遵守[仓库界面设计要求](../AGENTS.md#界面设计)；颜色、图标、菜单、焦点、动效令牌和布局沿用 [UI 约定](../docs/development.md#页面约定)。列表悬浮默认只用轻背景，不抬升、不添加装饰阴影。

## 性能与动效

所有动效和图标以性能与流畅度为先。桌面端的已有和新增动效都优先采用系统原生合成。只要目标平台能在保持外观、节奏、流畅度和交互行为的前提下独立播放该效果，就使用原生图层。新增动效从设计时选型；存量动效按组件逐步迁移，优先处理长时间播放或频繁触发的效果。

- 动画只改 `transform` 和 `opacity`。需要尺寸、位置或阴影变化时，用缩放、位移、裁剪或预先画好的伪元素淡入实现，不对宽高、边距、`top`/`left`、`box-shadow`、`filter` 做过渡。现有例外只有 `animateLayout` 在切换那一刻过渡网格列。
- CSS 过渡列出实际变化的属性，不写 `transition: all`。Web 实现优先使用 CSS 或 Web Animations，确需逐帧计算时才用局部的 `requestAnimationFrame`。
- `will-change` 只在动画开始前加、结束后移除，不写进常驻样式。新界面不使用 `backdrop-filter` 和大面积模糊。
- 图标统一走 [icons.js](assets/ui/icons.js) 与 SVG sprite，不引入图标字体，不为几个图标加载整套图标库，不用位图做界面图标；品牌标识用单色 SVG 路径。远程图标（网页 favicon、MCP 服务图标）由后端获取并缓存，前端固定尺寸占位、按需加载，失败退回字母或默认图标，加载前后布局不跳动。
- 长列表分页、折叠或按可见区域渲染；流式和刷新更新复用已有 DOM（[reconcile.js](assets/ui/reconcile.js)），不整段重建 `innerHTML`。先批量读布局再批量写样式，不在循环里交替读写造成强制重排。
- 滚动、输入、缩放监听用 passive 并节流到每帧最多一次；轮询只在页面可见时进行（[visible-poll.js](assets/ui/visible-poll.js)）。
- 新增动效、长列表或高频更新，在 DevTools Performance 中确认没有长任务和布局抖动，CPU 4 倍降速下仍然顺畅。

验证可见行为使用对应 `e2e/*.spec.js`，补充 Node 的控制器/会话测试。详情见 [代码地图](../docs/development.md#代码地图)，不要把只匹配 HTML 文本的断言当成操作验收。

### 动效的集中管理

- **统一定义。** 在共用 UI 层按用途定义可复用的动效，如运行指示、选中项滑动和面板进出。每种效果约定变化的属性、时长、缓动、循环条件和减少动态效果时的表现。时长与缓动取自 [ui.css](assets/ui.css) 的 `--motion-*`、`--ease-*` 令牌。侧栏和按钮若需不同转速，在同一效果上定义速度变体。
- **组件负责触发。** 组件提供业务状态、目标元素和必要的起止位置，保留布局、焦点和可访问名称。简单悬浮、按压反馈可直接使用共享 CSS 令牌和样式。需要脚本控制的效果在 [motion.js](assets/ui/motion.js) 登记，组件调用 `playMotion(元素, 效果名, 参数)`；折叠、位移等由组件提供实测几何数据。调用者通过 `finished` 和 `cancel()` 管理交互的完成与取消。
- **统一选择播放方式。** 共用入口按效果和宿主能力选择原生或 Web 实现，每个实例同时只启用一种。业务组件无需判断操作系统。动画交给所选实现自行推进，避免引入全局逐帧循环。
- **统一启停和清理。** 循环效果只在业务状态需要且目标可见时播放。重复收到同一状态时复用当前实例；页面隐藏、目标离开视口时停止，恢复可见后重新判断。状态被替换或组件卸载时取消旧实例并清理监听、临时 DOM 和原生图层。快速切换时，旧动画的完成回调不能覆盖最新状态。
- **统一处理「减少动态效果」。** 优先采用应用内设置，选择跟随系统时读取系统偏好；脚本沿用 `reducedMotion()`，CSS 与原生实现遵循同一选择。运行中切换设置也要生效。减少动态效果时用静态标识传达运行状态，面板、选中项等直接呈现目标状态，只保留必要的淡入淡出。

CSS 关键帧和播放选择器统一放在 [motion.css](assets/styles/motion.css)，组件样式保留布局、外观和引用令牌的交互过渡。第一个画面直接使用同一份 CSS 减动规则。侧栏、模型列表和文件预览用 `<formicand-spinner>` 表达忙碌状态。思考蚂蚁、状态文字扫光、运行时间线脉冲、按钮和保存指示等重复播放的 CSS 动画由共用入口监听浏览器的启停事件，移出视口或页面隐藏时暂停，结束或取消后释放观察。页面隐藏或启用减动时，正在执行的脚本过渡立即到达终态。

### 桌面动效的原生合成

判断依据是能否把图层内容和动画参数一次交给系统，让它自行播放到结束或取消。旋转、位移、缩放、透明度和预绘帧序列都适用，包括侧栏运行指示、对话等待效果，以及菜单、抽屉、列表项的短暂入场和退场。复合效果按职责拆分：例如流式消息由 Web 处理新文字、换行和布局，消息块独立的淡入可交给原生图层。浏览器端和平台尚未支持的效果使用等效的 Web 实现。

- **macOS**：主窗口通过[动效桥](../desktop/motion.cjs)接收可见图形的坐标、颜色、周期和相位，由 [Core Animation](../desktop/motion.mm) 播放。浏览器中的布局盒、可访问名称和点击目标保留在原位置。桌面开发和打包命令编译随包的 Node-API 模块。
- **Windows**：原生路径采用 Windows Composition 或 DirectComposition，由系统推进图层动画。先用侧栏转圈做实机对照，测量 Chromium 和桌面窗口管理器 DWM 的负载，再把验证过的能力复用于同类动效。
- **Linux**：保留 Web 实现，分别在 Wayland 和 X11 上采样。对开销明显的效果评估独立绘制区域，例如由客户端逐帧更新 Wayland 子表面，使主页面可以保持静止。

现有动效按绘制内容选择播放位置。业务组件继续使用统一入口。

| 界面动效                                                                       | macOS 绘制方式与交接条件                                                                                                                            |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |

桌面宿主负责原生图层的绘制与播放，通过可信桥接收启停、位置、裁剪和主题变化，避免逐帧 IPC。验证滚动、折叠和弹层遮挡时的图层位置与可见性。快速切换、卸载组件或切换「减少动态效果」后，确认画面符合最新状态，已停止的效果不再持续提交帧。

对照测量使用同一台目标设备、同一可见窗口和同一操作，保持其他动效状态一致。循环效果比较静止、Web 播放和原生播放；短暂过渡按相同节奏重复触发，比较帧耗时和掉帧。记录采样时长、桌面进程 CPU、Chromium 提交帧数和系统合成器负载；涉及续航或风扇的结论另测整机功耗或转速。
