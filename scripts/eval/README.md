# 提示词实测

用同一组真实任务比较提示词和开发流程的改动。2026-11-20 与 2026-11-23 的实测记录随设计文档一起归档，原文见 [架构决定历史](../../docs/adr-history.md)。

```sh
npm run build
node scripts/eval/run.mjs [--tasks fix,due] [--repeat 2] [--label 名字] [--context-window 40000]
```

- 会调用真实模型并产生费用。模型使用桌面版的设置：脚本把 `~/.formicand/model-config.json` 和 `credentials.json` 复制到临时目录，跑完删除；也可以用 `EVAL_MODEL_CONFIG`、`EVAL_CREDENTIALS` 指定。
- 每次运行另起一个后端，数据放在临时目录，不影响正在用的程序和数据。
- 每个任务从 `repo/` 复制一份示例仓库，建成 Git 仓库后交给 Main。Main 结束后，用 `hidden/` 里对应的测试检查结果。
- Main 提问时，脚本统一回答“按自己的判断决定”，并记一次提问。确认卡片（票、自定义 Agent）按用户同意处理，记为确认，不算提问。Main 停在问句上而检查没通过时，脚本发一次“继续。”，并记为中途停下。
- `--context-window` 把复制出来的模型设置里每个模型的上下文窗口改成给定值，并不再跟随接口自报的窗口，用来逼长会话中途换窗口。只改临时副本。
- 任务可以带预先写好的需求台账（`history.mjs`），项目建好后、Main 开始前写入。台账照长期功能写：十来条需求，规矩写在各自的现状里；日期规矩写在示例仓库的架构决定 `docs/adr/` 里，被取代的旧格式在 `docs/adr-history.md`。报告的“新建需求”一栏列出 Main 新加的需求。
- 任务可以带后续消息（同一会话里依次发）和后续会话（同一项目里新开会话），用来测长会话和跨会话记忆。
- 结果写到 `results/<名字>/`：每次运行一份 JSON，加上完整的任务详情；`summary.md` 汇总结果和每次的最终汇报。`results/` 不提交。

| 任务            | 类型 | 看什么                                                                                                                                                       |
| --------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `fix`           | 能力 | 修好挂掉的测试，只改出错的文件，不派协作者                                                                                                                   |
| `filter`        | 能力 | 跨文件加选项和测试                                                                                                                                           |
| `due`           | 能力 | 多部分需求：是否建开发记录、是否合入、汇报                                                                                                                   |
| `team`          | 能力 | 多人在用、能分开做的需求：是否拆票、派审查、终审后合入。提示里不提票和审查                                                                                   |
| `long`          | 压缩 | 一个会话里连加五个命令，配合 `--context-window`：换窗口后是否仍守住第一条消息里的三条规矩、CHANGELOG 不重复记                                                |
| `memory`        | 记忆 | 第一个会话里纠正一次做法，第二个会话是否照做；报告里“记在”一栏列出记到了记忆还是 AGENTS.md                                                                   |
| `history`       | 检索 | 老项目：规矩写在台账十来条长期功能的现状和仓库的架构决定里，旧日期格式已被取代；提示只说“按之前定下的规矩来”。报告里“查台账”一栏列出 Main 查了几次、查的什么 |
| `history-alias` | 检索 | 用户说“添加时间”，台账里叫“创建日期”：要用的规矩只在这条的现状里；不该新建需求                                                                               |
| `history-misc`  | 检索 | 与任何功能无关的小改动（改版本号）：不该新建需求                                                                                                             |
| `history-tidy`  | 检索 | 台账里同一块功能记成了两条；开跑前先记下 9 次已合入的开发，这次导出改动合入后正好满 10 次，`next` 提示维护台账，两条应合并成一条                             |
| `ask`           | 行为 | 直接回答，不派协作者，不改文件                                                                                                                               |
| `rename`        | 行为 | 多文件改名，不中途停下，旧数据仍能读                                                                                                                         |
